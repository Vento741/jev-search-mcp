## 1. Что это и когда применять

`jev_search` проверяет каждую непустую строку нескольких небольших файлов и отвечает, выражает ли она заданное намерение. Слова при этом могут не совпадать. Запрос «клиент просит вернуть деньги» находит строку «спишите, пожалуйста, второй платёж обратно», которую не найдёт `grep "вернуть"`.

**Когда применять:**

- нужная мысль может быть записана разными словами: заметки, переписка, тикеты, решения в документации, сообщения в логах;
- важно отрицание: по замыслу CLI модель должна учитывать отрицание (в его инструкции: «Respect negation»), так что строка «возврат не предусмотрен» ожидаемо не станет совпадением для запроса «мы обещаем возврат»; на русском это не измерялось, проверьте на своих данных;
- `grep` уже дал кандидатов, но вы подозреваете, что часть мест написана иначе.

**Когда не применять:**

| Задача | Чем решать |
|---|---|
| Точное имя, идентификатор, символ, код ошибки, номер заказа | `grep`/`rg`, поиск по коду |
| Поиск по исходному коду (`.py`, `.ts` и т. п.) | обычные инструменты агента; CLI принимает только `.txt` `.md` `.csv` `.jsonl` `.log` |
| Весь репозиторий или большой архив документов | сначала сузьте круг: имена файлов, ссылки, `grep`; за один вызов проходит ≤ 64 строк |
| Подсчёты и аналитика («сколько тикетов про оплату») | скрипт или таблица; `jev_search` оценивает строки, а не считает |
| Мысль, растянутая на несколько строк | модель оценивает **каждую строку отдельно**; абзац, разбитый переносами, теряет смысл. Лучше подходят тексты «одна мысль — одна строка» |

> [!NOTE]
> Это **дополнительный** поиск. Он не заменяет точный: лучший результат даёт объединение совпадений `grep` и `jev_search` с последующим чтением исходного контекста.

## 2. Как это устроено, что уходит провайдеру и сколько стоит

```mermaid
flowchart LR
    A["Агент"] -->|"jev_search(query, files)"| B["jev-search-mcp"]
    B -->|"подпроцесс, ключ из окружения"| C["jev-search CLI"]
    C -->|"1 HTTPS-запрос"| D["OpenRouter → TypeSafe Jev"]
```

1. Агент вызывает инструмент `jev_search` с запросом и 1–8 **абсолютными** путями.
2. Сервер запускает закреплённую версию CLI `jev-search` из своего окружения. Ключ CLI берёт из переменной `JEV_SEARCH_API_KEY`; в аргументах ключ не передаётся никогда.
3. CLI проверяет файлы (типы, размеры, скрытые пути, похожий на секрет текст), затем отправляет **один** запрос без повторов.
4. Ответ приходит агенту: каждая непустая строка с файлом, номером строки (с 1), оценкой `probability` и флагом `match` (`probability >= 0.5`), плюс `meta` со стоимостью. С `top_k` добавляется `ranked_results`: только совпадения, лучшие первыми.

**Что уходит провайдеру.** Запрос и **все** выбранные непустые строки, а не только совпадения. Пути к файлам в запрос не входят, но сам текст может их содержать. На маршруте по умолчанию OpenRouter может передать запрос только TypeSafe: запасные провайдеры отключены, сбор данных запрещён (`data_collection: deny`). Этот блок маршрутизации CLI отправляет только через OpenRouter; при прямом доступе к TypeSafe его нет. TypeSafe в [политике конфиденциальности](https://typesafe.ai/legal/privacy-policy) обещает не обучать модели на входных данных; нулевое хранение данных в [юридической документации](https://docs.typesafe.ai/legal) предлагается только корпоративным клиентам. Это разные гарантии. Решение о том, какие данные можно отправлять, принимаете вы или ваша организация.

Учтите и вторую сторону: ответ инструмента с исходными строками и абсолютными путями читает сам агент, то есть его модель, как при обычном чтении файла.

**Стоимость.** Каждый реальный поиск платный. Поиск по файлу из двух строк стоил около **$0.00002** и занял ~0.7 с (замер от 2026-09-30, цены меняются). Цена растёт с числом строк. Точная сумма каждого вызова приходит в `meta.cost`, итог виден в кабинете OpenRouter.

> [!WARNING]
> Таймаут, сетевой сбой или ответ, не прошедший проверку, **не отменяют** списание: запрос мог дойти до провайдера или уже был им обработан. CLI никогда не повторяет запрос сам; не просите агента повторять вслепую. Если `cost` нет в ответе (ошибка или прямой маршрут TypeSafe), это значит «неизвестно», а не «бесплатно».

`dry_run: true` всегда бесплатен: он ничего не отправляет, не читает ключ и показывает ровно те строки, которые ушли бы провайдеру.

## 3. Установка

**Нужны:** [uv](https://docs.astral.sh/uv/) и [git](https://git-scm.com/downloads). Python ставить отдельно не нужно: если подходящего (3.11+) нет, uv скачает его сам.

### Шаг 1. uv

```powershell
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

```bash
# Linux / VPS / macOS: без sudo, uv ставится в ~/.local/bin
curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"   # или откройте новый терминал
uv --version
```

На VPS всё ставится в домашний каталог пользователя, права администратора не нужны. Если на сервере нет `git` (`git --version`), попросите администратора его установить.

### Шаг 2. Сервер

Основной способ: установить сервер как инструмент uv с закреплённым тегом релиза.

```bash
uv tool install git+https://github.com/Vento741/jev-search-mcp@v0.1.0
jev-search-mcp --version   # выведет 0.1.0
```

Исполняемый файл окажется в `~/.local/bin` (Windows: `C:\Users\you\.local\bin\jev-search-mcp.exe`). Если оболочка его не находит, выполните `uv tool update-shell` и откройте новый терминал.

Тег в конце адреса (`@v0.1.0`) закрепляет версию: пока вы его не поменяете, у всех коллег одинаковый код, а версия CLI `jev-search` закреплена внутри пакета на конкретном коммите.

<details>
<summary><b>Альтернатива: запуск через <code>uvx</code> без установки</b></summary>

Клиент может запускать сервер командой:

```bash
uvx --from git+https://github.com/Vento741/jev-search-mcp@v0.1.0 jev-search-mcp
```

Минусы: старт медленнее, при каждом запуске uv может обращаться к GitHub, а первый запуск скачивает зависимости и может не уложиться в таймаут подключения клиента. Прогрейте кэш заранее той же командой с `--version`:

```bash
uvx --from git+https://github.com/Vento741/jev-search-mcp@v0.1.0 jev-search-mcp --version
```

</details>

### Обновление, проверка версии и удаление

```bash
# обновить до нового тега релиза
uv tool install --force git+https://github.com/Vento741/jev-search-mcp@<новый-тег>
# посмотреть установленную версию
uv tool list
# удалить
uv tool uninstall jev-search-mcp
```

После обновления перезапустите MCP-клиент, чтобы он запустил новую версию сервера.

## 4. Ключ API

### Создание ключа

1. Откройте <https://openrouter.ai/settings/keys> и создайте **отдельный** ключ для jev-search.
2. Сразу задайте для него **лимит расходов** (credit limit). Это единственная настоящая граница бюджета: CLI ограничивает число запросов (один за вызов), но не деньги.
3. Ключ личный. У каждого коллеги должен быть **свой** ключ с собственным лимитом; не пересылайте ключи в мессенджерах, почте, задачах и чатах с агентом.

> [!WARNING]
> Никогда не вставляйте ключ в чат с агентом, в промпты, в `CLAUDE.md`/`AGENTS.md`, в Git и в аргументы команд. Не просите агента вывести или проверить значение ключа. Ниже все команды читают ключ через скрытый ввод, поэтому он не отображается и не попадает в историю команд.

### Кому какой способ нужен

Сервер берёт ключ из окружения, которое ему передаёт клиент. Клиенты передают его по-разному:

| Клиент | Передаёт ваши переменные окружения? | Где хранить ключ |
|---|---|---|
| Claude Code (терминал, расширения VS Code и JetBrains) | **да**, всё своё окружение | пользовательская переменная `JEV_SEARCH_API_KEY` |
| Claude Agent SDK | передавайте явно | `env` в конфиге сервера из `os.environ` ([пример](#claude-agent-sdk-python)) |
| Claude Desktop | **нет**, только небольшой стандартный набор (`PATH`, `APPDATA`, `USERPROFILE` и т. п.) | блок `env` в `claude_desktop_config.json` |
| Другие клиенты на MCP SDK | обычно **нет**, как Claude Desktop | блок `env` в конфиге клиента |
| Сервис systemd или оркестратор | только то, что задано в его конфигурации | `EnvironmentFile=` или секреты оркестратора |

### Claude Code на Windows

```powershell
# вставьте ключ по запросу, затем полностью перезапустите терминал и MCP-клиент
$s = Read-Host 'Вставьте ключ OpenRouter' -AsSecureString
[Environment]::SetEnvironmentVariable('JEV_SEARCH_API_KEY', [System.Net.NetworkCredential]::new('', $s).Password, 'User')
```

Проверить, что переменная задана, не показывая её значения:

```powershell
[Environment]::GetEnvironmentVariable('JEV_SEARCH_API_KEY', 'User').Length   # число > 0
```

> [!IMPORTANT]
> Уже запущенные программы новую переменную **не видят**. Нужен **полный** перезапуск: закройте все окна VS Code (главный процесс; *Reload Window* не помогает), все терминалы и сессии Claude Code, затем откройте заново. Если VS Code запущен из терминала, он унаследует окружение этого терминала, поэтому терминал тоже откройте новый.

### Claude Code на Linux и VPS

**Вариант А — `~/.bashrc`** (как в README):

```bash
# вставьте ключ по запросу; он не отображается и не попадает в историю команд
read -rsp 'Вставьте ключ OpenRouter: ' K; echo
echo "export JEV_SEARCH_API_KEY='$K'" >> ~/.bashrc; unset K; chmod 600 ~/.bashrc; source ~/.bashrc
```

**Вариант Б — отдельный файл `~/.config/jev-search.env`** (удобнее менять ключ и подключать к службам):

```bash
mkdir -p ~/.config
read -rsp 'Вставьте ключ OpenRouter: ' K; echo
( umask 077; printf "JEV_SEARCH_API_KEY='%s'\n" "$K" > ~/.config/jev-search.env ); unset K
chmod 600 ~/.config/jev-search.env
echo '[ -f ~/.config/jev-search.env ] && { set -a; . ~/.config/jev-search.env; set +a; }' >> ~/.bashrc
source ~/.bashrc
```

Проверка без вывода значения:

```bash
[ -n "$JEV_SEARCH_API_KEY" ] && echo "ключ задан" || echo "ключ не задан"
```

Нужен именно `~/.bashrc`: неинтерактивные и не-login оболочки не читают `~/.profile`. Сессии Claude Code, запущенные **до** изменения (например, в старом окне `tmux`), ключа не увидят, их нужно перезапустить. На macOS (zsh) используйте `read -rs 'K?Вставьте ключ OpenRouter: '` и `~/.zshrc`.

Службы `~/.bashrc` не читают. Для сервиса systemd, который запускает агента, подключите тот же файл: `EnvironmentFile=/home/me/.config/jev-search.env` в секции `[Service]`.

### Claude Desktop и другие клиенты

Ключ указывается в блоке `env` конфига клиента ([пример](#claude-desktop)). Он хранится **открытым текстом**, поэтому файл конфига:

- лежит только в вашем профиле и не коммитится;
- не синхронизируется через облачные папки и не пересылается коллегам (пусть каждый впишет свой ключ);
- при утечке ключ отзывается в <https://openrouter.ai/settings/keys> и заменяется новым.

### Смена и отзыв ключа

Отзовите старый ключ в кабинете OpenRouter, создайте новый с лимитом и повторите команду записи ключа. В варианте А сначала удалите старую строку `export JEV_SEARCH_API_KEY=...` из `~/.bashrc`, в варианте Б файл просто перезаписывается. Затем полностью перезапустите клиент.

## 5. Подключение клиентов

Имя сервера во всех примерах — `jev-search`, инструмент — `jev_search`, поэтому полное имя инструмента в Claude — `mcp__jev-search__jev_search`.

### Claude Code

**Для себя, во всех проектах** (user scope):

```bash
claude mcp add --scope user jev-search -- jev-search-mcp
claude mcp list          # jev-search должен быть в статусе Connected
```

Ключ сервер получит из вашего окружения (см. [раздел 4](#4-ключ-api)). Не передавайте его через `claude mcp add -e JEV_SEARCH_API_KEY=...`: так ключ попадёт в историю команд и открытым текстом в `~/.claude.json`.

**Для всей команды в репозитории** (project scope). Команда создаёт в корне проекта файл `.mcp.json`, который можно закоммитить:

```bash
claude mcp add --scope project jev-search -- jev-search-mcp
```

Секрета в файле нет и быть не должно: блок `env` для ключа не нужен, потому что Claude Code передаёт серверу всё своё окружение.

```json
{
  "mcpServers": {
    "jev-search": {
      "type": "stdio",
      "command": "jev-search-mcp",
      "args": []
    }
  }
}
```

При первом открытии проекта Claude Code спросит каждого участника, разрешить ли серверы из `.mcp.json`. Каждый коллега ставит сервер (`uv tool install ...`) сам, и у каждого `JEV_SEARCH_API_KEY` с **собственным** ключом должен быть задан в **его** окружении ([раздел 4](#4-ключ-api)); иначе реальный поиск вернёт ошибку `set JEV_SEARCH_API_KEY ...`, а `dry_run` будет работать.

Полезные команды: `claude mcp get jev-search` (конфигурация), `claude mcp remove jev-search` (удалить), `/mcp` внутри сессии (статус и инструменты).

Чтобы Claude Code не спрашивал разрешения на каждый вызов, добавьте `mcp__jev-search__jev_search` в `permissions.allow` в настройках. Это убирает и подтверждение отправки данных провайдеру, а каждый реальный вызов платный; разрешайте, только если правила из [раздела 7](#7-правила-для-claudemd-и-agentsmd) у вас настроены.

### Claude Desktop

1. Узнайте полный путь: `where.exe jev-search-mcp` (Windows) или `which jev-search-mcp` (macOS/Linux). Графические приложения часто не видят `~/.local/bin` в `PATH`, поэтому путь нужен полный.
2. Откройте конфиг: *Settings → Developer → Edit Config* или напрямую `%APPDATA%\Claude\claude_desktop_config.json` (Windows), `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS).
3. Добавьте сервер (если `mcpServers` уже есть, допишите внутрь), затем **полностью** закройте Claude Desktop (в том числе из трея) и откройте снова.

```json
{
  "mcpServers": {
    "jev-search": {
      "command": "C:\\Users\\you\\.local\\bin\\jev-search-mcp.exe",
      "env": { "JEV_SEARCH_API_KEY": "<ваш-ключ>" }
    }
  }
}
```

Вписывайте ключ, открыв файл в редакторе, и никому не отправляйте файл целиком.

### Claude Agent SDK (Python)

Сверено с [документацией Agent SDK по MCP](https://code.claude.com/docs/en/agent-sdk/mcp) на 2026-09-30. SDK ставится отдельно (`pip install claude-agent-sdk`) и требует **собственной** аутентификации Claude; это не ключ jev-search.

```python
import asyncio
import os

from claude_agent_sdk import ClaudeAgentOptions, ResultMessage, SystemMessage, query


async def main():
    options = ClaudeAgentOptions(
        mcp_servers={
            "jev-search": {
                "type": "stdio",
                "command": "jev-search-mcp",  # на сервере надёжнее полный путь из `which`
                "env": {"JEV_SEARCH_API_KEY": os.environ["JEV_SEARCH_API_KEY"]},
            }
        },
        allowed_tools=["mcp__jev-search__jev_search"],
    )
    prompt = (
        "Запусти jev_search с dry_run=true для файла /home/me/notes/sample.txt "
        "и запроса «приветствие». Покажи, какие строки были бы отправлены."
    )
    async for message in query(prompt=prompt, options=options):
        if isinstance(message, SystemMessage) and message.subtype == "init":
            for server in message.data.get("mcp_servers", []):
                if server.get("status") == "failed":
                    print(f"MCP-сервер {server['name']} не подключился")
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)


asyncio.run(main())
```

- Ключ передаётся явно из окружения процесса: `os.environ[...]` сразу упадёт с `KeyError`, если переменная не задана, и значение нигде не печатается.
- `allowed_tools` лишь разрешает вызов без подтверждения; лимит вызовов на задачу задайте в промпте или в логике оркестратора.
- Сигнатуры SDK развиваются; если пример не запускается, сверьтесь с актуальной документацией по ссылке выше.

### Любой MCP-клиент или оркестратор

Используйте стандартную stdio-конфигурацию. Если клиент не документирует, что передаёт всё ваше окружение, указывайте ключ в `env`:

```json
{
  "mcpServers": {
    "jev-search": {
      "command": "jev-search-mcp",
      "args": [],
      "env": { "JEV_SEARCH_API_KEY": "<ваш-ключ>" }
    }
  }
}
```

С `uvx`: `"command": "uvx"`, `"args": ["--from", "git+https://github.com/Vento741/jev-search-mcp@v0.1.0", "jev-search-mcp"]`.

Сервер не открывает портов, не пишет в файлы и работает, пока клиент держит его stdin/stdout. Одного экземпляра на сессию агента достаточно. Проверить сервер без агента можно в [MCP Inspector](https://github.com/modelcontextprotocol/inspector): `npx @modelcontextprotocol/inspector jev-search-mcp` (нужен Node.js).

### Прямой доступ к TypeSafe

По умолчанию запросы идут через OpenRouter. Для прямого доступа к TypeSafe нужен ключ, **выданный TypeSafe**: ключи OpenRouter и TypeSafe не взаимозаменяемы.

```json
"env": {
  "JEV_SEARCH_API_KEY": "<ключ TypeSafe>",
  "JEV_SEARCH_PROVIDER": "typesafe"
}
```

Для Claude Code задайте `JEV_SEARCH_PROVIDER=typesafe` пользовательской переменной так же, как ключ. `JEV_SEARCH_MODEL` меняет модель (по умолчанию `typesafe/jev-1.13` через OpenRouter и `jev-1.13.0` напрямую). Прямой маршрут автор CLI проверял только локальными контрактными тестами; ответ TypeSafe может не содержать `cost`, и это означает «неизвестно», а не «бесплатно». Учтите: блок маршрутизации OpenRouter (только TypeSafe, без запасных провайдеров, `data_collection: deny`) на прямом маршруте не отправляется; действуют условия вашего договора с TypeSafe.

## 6. Сценарии

Общая схема для любого сценария:

1. **Сориентироваться:** имена файлов, оглавления, теги, ссылки, `grep`.
2. **Выбрать** 1–8 файлов или выборок, вместе ≤ 16 КБ и ≤ 64 строк. Не ограничивайтесь только файлами с совпадениями `grep`, иначе смысловой поиск не найдёт то, что вы исключили заранее.
3. **Искать:** `jev_search` (для незнакомых или чувствительных данных сначала `dry_run`).
4. **Объединить** с совпадениями `grep`, перечитать контекст вокруг найденных строк, ответить со ссылками на файл и строку.

Все запросы агенту ниже можно вставлять как есть, заменив пути на свои.

### Как формулировать запрос

- Описывайте **намерение целым утверждением**, а не набором ключевых слов: «Клиент сообщает, что деньги списали дважды» лучше, чем «двойное списание».
- Упоминание слова не считается совпадением: модель проверяет, выражает ли строка смысл запроса.
- Запрос — одна строка, ≤ 512 байт (кириллица занимает 2 байта на символ, то есть около 250 символов), без фрагментов вида `password:` или `token=`: их CLI примет за секрет.
- Качество на русском языке отдельно не измерялось. Для важной задачи проверьте поиск на небольшом примере, где вы знаете правильный ответ.
- Оценки удобны для сортировки, но не являются откалиброванными вероятностями. Ссылайтесь на строки, а не на числа.

### Сценарий 1. Документация проекта и ADR

**Задача.** Понять, какие архитектурные решения ограничивают новый сервис, например выбор хранилища, даже если в ADR нет слов «база данных».

**Как выбрать файлы.** Посмотрите заголовки ADR (`ls docs/adr`, первая строка каждого файла) и отберите до 8 коротких кандидатов. Длинные ADR сократите до разделов «Решение» и «Последствия» (см. [сценарий 6](#сценарий-6-большой-файл-по-фрагментам)). Помните про 64 строки на все файлы вместе.

**Запрос агенту:**

> Найди в /home/me/project/docs/adr решения, которые ограничивают выбор хранилища данных для нового сервиса. Сначала посмотри заголовки ADR и сделай grep по «PostgreSQL|база|хранилищ|storage». Затем выбери до 8 самых вероятных ADR (или их разделы «Решение») в пределах лимитов jev_search и выполни поиск с запросом «Решение ограничивает, какое хранилище данных может использовать сервис». Объедини результаты grep и jev_search, перечитай найденные места и дай список: файл, строка, суть ограничения.

**Что ожидать.** Ожидаемо — совпадения вроде «Все сервисы работают с общим кластером, отдельные экземпляры не разворачиваются», которые `grep` мог пропустить. Проверка: агент должен процитировать строку и указать её номер; откройте файл и убедитесь, что смысл совпадает.

### Сценарий 2. Заметки Obsidian и «второй мозг»

**Задача.** Найти в заметках места, где вы откладывали решение или сомневались, хотя слово «сомневаюсь» могло не прозвучать.

**Как выбрать файлы.** Сузьте круг по папке, дате, тегам и ссылкам: например, ежедневные заметки за последнюю неделю. Выберите до 8 заметок, вместе ≤ 64 строк; длинные заметки сократите до нужных разделов. Метаданные (frontmatter) тоже считаются строками. Служебная папка `.obsidian` не нужна и всё равно отклоняется (скрытый путь).

**Запрос агенту:**

> В заметках C:\Users\you\Obsidian\Vault\Журнал за 2026-09-22…2026-09-28 найди места, где я откладываю решение или не уверен в выбранном пути. Сначала grep по «отлож|не уверен|сомнева|потом решу». Затем выбери до 8 заметок в пределах лимитов jev_search и выполни поиск с запросом «Автор откладывает решение или сомневается в выбранном варианте». Выведи список: заметка, строка, цитата; отметь, что нашёл grep, что jev_search, что оба.

**Что ожидать.** Ожидаемо — строки вроде «Вернусь к этому после релиза» или «Пока оставлю как есть, посмотрим». Если хранилище лежит в облачной папке (OneDrive и т. п.), файлы могут оказаться точками повторной обработки (reparse points) и будут отклонены; тогда агент скопирует выбранные заметки во временную папку (см. [диагностику](#9-диагностика)).

### Сценарий 3. Разбор логов на VPS

**Задача.** Найти в свежем логе признаки проблемы, описанные разными формулировками: таймауты, отказы, «повторная попытка», «connection reset».

**Как выбрать файлы.** Сделайте выборку последних строк во временную папку. В пути не должно быть частей, начинающихся с точки (`/home/me/.cache/...` отклоняется). Общий каталог вроде `/tmp/jev` на многопользовательском сервере может создать или прочитать кто-то другой, поэтому создавайте личный каталог через `mktemp -d` (права 700):

```bash
D=$(mktemp -d /tmp/jev.XXXXXX)
tail -n 60 /var/log/myapp/app.log > "$D/app-tail.log"
# или из journald:
journalctl -u myapp -n 60 --no-pager -o short-iso > "$D/myapp.log"
wc -c -l "$D/app-tail.log"   # должно быть ≤ 16384 байт и ≤ 64 строк
```

Если в строках лога есть что-то вроде `token=...` или `password: ...`, CLI отклонит весь файл (`possible secret rejected`). Не отправляйте такие строки: удалите их из **копии**, заменив пустыми строками. Пустые строки не отправляются, а нумерация сохраняется. Команда для GNU sed (Linux):

```bash
sed -E -i 's/.*(sk-or-|PRIVATE KEY|(api[_-]?key|password|secret|token)\s*[=:]).*//I' "$D/app-tail.log"
```

> [!WARNING]
> Проверка CLI на секреты эвристическая (не ловит Bearer-токены, JWT, пароли в URL, тело PEM-ключа); всегда просматривайте вывод `dry_run` перед реальным поиском.

**Запрос агенту:**

> На этом сервере в /var/log/myapp/app.log что-то периодически ломается. Создай личный временный каталог командой mktemp -d /tmp/jev.XXXXXX и сделай в нём выборку tail -n 60 в файл app-tail.log, проверь лимиты. Сначала сделай dry_run и покажи мне rows; реальный поиск только после моего «отправляй». Затем выполни jev_search с запросом «Строка сообщает о сбое связи с внешним сервисом или о повторной попытке запроса» и top_k=10. Дай список совпадений с временными метками и объясни, что, по-твоему, происходит. В конце удали временный каталог.

**Что ожидать.** Ожидаемо в `ranked_results` окажутся самые подходящие строки. Номера строк относятся к выборке; для привязки к исходному логу используйте временные метки. Не оставляйте выборки после работы: `rm -rf "$D"`.

### Сценарий 4. Тикеты поддержки в CSV

**Задача.** Найти обращения на определённую тему в выгрузке тикетов, где клиенты пишут своими словами.

**Как выбрать файлы.** CSV читается как **текст по строкам**, а не как таблица. Поэтому:

- в каждой строке должен быть идентификатор тикета: он надёжнее номера строки;
- ячейки с переносами внутри кавычек разорвут тикет на несколько строк; такие поля лучше свести в одну строку при выгрузке;
- строка заголовка тоже оценивается, ничего страшного, но она занимает одну из 64 строк;
- оставьте только нужные столбцы (id, дата, текст), чтобы не отправлять лишние персональные данные.

Выборка по 60 тикетов: `D=$(mktemp -d /tmp/jev.XXXXXX); sed -n '2,61p' tickets.csv > "$D/tickets-r2-61.csv"`.

**Запрос агенту:**

> В /home/me/support/tickets-2026-09.csv (id, дата, текст) найди обращения, где клиент сообщает, что с него списали деньги дважды. Сначала grep по «дважды|два раза|повторн|двойн». Затем возьми первые 60 тикетов в личный временный каталог (mktemp -d /tmp/jev.XXXXXX), сделай dry_run jev_search и покажи мне payload_bytes и число строк. После моего подтверждения выполни реальный поиск с запросом «Клиент сообщает, что оплату с него списали повторно» и top_k=15 и дай список id тикетов с цитатами. В конце удали временный каталог.

**Что ожидать.** Ожидаемо — тикеты вроде «Почему в выписке две одинаковые суммы за подписку?». Больше 64 тикетов за вызов не пройдёт; несколько вызовов — это несколько списаний, поэтому о массовом разборе договоритесь с агентом заранее.

### Сценарий 5. grep и смысловой поиск вместе

**Задача.** Найти в политиках компании все места, где мы обещаем вернуть деньги, включая формулировки без слова «возврат», и не принять отказ за обещание.

**Как выбрать файлы.** `rg -n -i "возврат|вернуть|вернём|refund" docs/policies` даёт лексические совпадения и список файлов. Для `jev_search` возьмите эти файлы (или их разделы) **и** 1–2 соседних раздела без совпадений: именно там обычно прячутся синонимичные формулировки.

**Запрос агенту:**

> Найди в /home/me/company/docs/policies все места, где компания обещает вернуть деньги клиенту. Шаг 1: rg -n -i по «возврат|вернуть|вернём|refund». Шаг 2: выбери разделы с совпадениями и соседние разделы без них, в пределах лимитов jev_search, и выполни поиск с запросом «Компания обещает вернуть клиенту деньги». Шаг 3: объедини результаты в таблицу «файл:строка | цитата | нашёл grep / jev / оба» и перечитай контекст каждой строки.

**Что ожидать.**

- ожидаемо `jev_search` добавит строки вроде «Мы компенсируем стоимость неиспользованного периода», которых нет в `grep`;
- строка «Возврат за цифровые товары не производится» попадёт в `grep`, но ожидаемо не станет совпадением в `jev_search` (проверьте на своих данных): по замыслу CLI модель должна учитывать отрицание (в его инструкции: «Respect negation»), но на русском это не измерялось;
- итог — объединение, а не пересечение: строки, найденные только `grep`, не выбрасывайте, а перечитайте.

### Сценарий 6. Большой файл по фрагментам

**Задача.** Найти смысловые совпадения в файле на тысячи строк, не нарушая лимитов и не теряя привязки к исходным номерам строк.

**Как выбрать файлы.** CLI ничего не обрезает сам: файл больше лимита вызовет ошибку. Нарежьте проверенные фрагменты и укажите диапазон строк исходника **в имени файла**. Тогда строка *N* во фрагменте `handbook.L1201-1260.md` — это строка *1200 + N* в исходном файле.

```bash
D=$(mktemp -d /tmp/jev.XXXXXX)   # на macOS: mkdir -p ~/jev-tmp (там /tmp — симлинк)
rg -n -i "отпуск|выходн" /home/me/docs/handbook.md | head   # найти опорные места
sed -n '1201,1260p' /home/me/docs/handbook.md > "$D/handbook.L1201-1260.md"
```

```powershell
New-Item -ItemType Directory -Force "$env:TEMP\jev" | Out-Null
Get-Content -Encoding UTF8 C:\Users\you\docs\handbook.md |
  Select-Object -Skip 1200 -First 60 |
  Set-Content -Encoding UTF8 "$env:TEMP\jev\handbook.L1201-1260.md"
```

В Windows PowerShell 5.1 `Set-Content -Encoding UTF8` добавляет в начало файла метку BOM. CLI её принимает, но она станет частью текста первой строки. В PowerShell 7+ используйте `-Encoding utf8NoBOM`.

Несколько коротких окон (например, 4 фрагмента по 10 строк) обычно полезнее одного длинного: так можно захватить и места с совпадениями `grep`, и разделы без них. Все окна вместе должны уложиться в 64 строки.

**Запрос агенту:**

> В /home/me/docs/handbook.md (около 3000 строк) найди правила, по которым сотрудник может работать не из офиса. Сначала grep по «удалён|из дома|remote|офис». Создай личный временный каталог (mktemp -d /tmp/jev.XXXXXX) и нарежь в него до 4 окон по 10 строк вокруг совпадений и 1–2 окна по 10 строк из разделов без совпадений (всего ≤ 64 строк), указывая диапазон строк исходника в имени файла (handbook.L<начало>-<конец>.md). Выполни jev_search по всем окнам сразу, пересчитай номера строк в исходные и дай ответ со ссылками handbook.md:<строка>. В конце удали временный каталог.

**Что ожидать.** Ожидаемо — ответ со ссылками на строки **исходного** файла. Проверка: откройте 1–2 ссылки и убедитесь, что номер указывает на процитированную строку.

### Сценарий 7. dry_run перед отправкой конфиденциального

**Задача.** Убедиться, что именно уйдёт провайдеру, прежде чем искать по договорам, персональным данным или внутренней переписке.

**Как выбрать файлы.** Как обычно, но первым шагом всегда `dry_run: true`. Это бесплатно, не требует ключа и сети.

**Запрос агенту:**

> Подготовь поиск по /home/me/legal/contract-2026.md с запросом «Сторона вправе расторгнуть договор в одностороннем порядке». Сначала выполни jev_search с dry_run=true и покажи мне: список строк из rows, payload_bytes, модель и провайдера. Реальный поиск не запускай, пока я не отвечу «отправляй».

**Что ожидать.** Ожидаемо — ответ с `"mode": "dry-run"`: `rows` — ровно те строки, что уйдут провайдеру, `model` и `provider` — куда именно. Если в строках есть то, что отправлять нельзя, уберите это из копии файла и повторите `dry_run`. После вашего «отправляй» агент выполнит тот же вызов без `dry_run`.

## 7. Правила для CLAUDE.md и AGENTS.md

Добавьте блок в `CLAUDE.md` или `AGENTS.md` проекта и подставьте свои значения в угловые скобки:

```markdown
## Смысловой поиск jev_search
- jev_search дополняет точный поиск, а не заменяет его: сначала имена файлов, ссылки и grep, затем 1–8 небольших файлов или выборок по абсолютным путям (вместе ≤ 16 КБ и ≤ 64 строк).
- Большие файлы не отправляй целиком: делай выборки в личную временную папку без точки в пути (например, из mktemp -d /tmp/jev.XXXXXX; на macOS — ~/jev-tmp), указывай диапазон строк исходника в имени файла и приводи номера строк к исходным.
- Всё выбранное и запрос уходят провайдеру (OpenRouter → TypeSafe). Разрешено: <папки и типы данных>. Остальное — только после dry_run и моего подтверждения.
- Каждый реальный вызов платный: не больше <N> вызовов на задачу без спроса; после ошибки или таймаута не повторяй без моего согласия.
- Объединяй совпадения с результатами grep, перечитывай контекст и ссылайся на файл:строку, а не на оценки.
- Никогда не выводи, не запрашивай и не ищи значение JEV_SEARCH_API_KEY.
```

## 8. Ограничения и справочник ошибок

### Ограничения

| Ограничение | Значение |
|---|---|
| Файлов за вызов | 1–8, абсолютные пути, без каталогов и масок, без повторов |
| Типы файлов | `.txt` `.md` `.csv` `.jsonl` `.log`, UTF-8 без управляющих символов |
| Общий объём | ≤ 16 384 байт **и** ≤ 64 строк во всех файлах вместе; пустые строки считаются, но не отправляются |
| Длина строки | ≤ 2 048 байт |
| Запрос | одна строка, ≤ 512 байт, без фрагментов, похожих на секрет |
| Пути | никакая часть пути не начинается с `.` и не содержит `secret`, `credential`, `password`, `id_rsa`; без символических ссылок и reparse points; в Windows без сетевых путей (`\\server\...`) |
| Сеть | один запрос за вызов, без повторов и перенаправлений |
| Таймаут | 330 с на вызов в обёртке (сетевой таймаут CLI — 300 с) |

Для кириллицы 16 КБ — это примерно 8 000 символов.

### Справочник ошибок

Ошибки приходят агенту текстом. Они делятся на две группы: ошибки **до отправки** (проверка параметров, файлов, запроса и ключа) ничего не стоят, а ошибки **при и после отправки** означают, что запрос мог дойти до провайдера и быть оплачен.

| Текст ошибки | Причина | Что делать |
|---|---|---|
| **До отправки: списания нет** | | |
| `files must be absolute paths (the server's working directory is arbitrary)` | передан относительный путь | передать полный путь: `/home/me/...` или `C:\Users\you\...` |
| `... validation error ...` | параметры вне схемы: больше 8 файлов, пустой список, `top_k` вне 1–64, неверный тип | исправить параметры вызова |
| `disallowed filename` | неподходящее расширение; часть пути начинается с `.` или содержит `secret`/`credential`/`password`/`id_rsa`; в Windows сетевой путь, зарезервированное имя (`CON`, `NUL`…) или имя, оканчивающееся пробелом или точкой | скопировать нужный фрагмент в папку без таких частей пути (например, созданную `mktemp -d /tmp/jev.XXXXXX`) и с допустимым расширением |
| `symlink rejected` | файл или одна из родительских папок — символическая ссылка. На macOS `/tmp` и `$TMPDIR` — симлинки | указать реальный путь или скопировать файл; на macOS используйте каталог в домашней папке без точки, например `~/jev-tmp` |
| `reparse point rejected` | Windows: файл или папка — точка повторной обработки (junction, облачная папка вроде OneDrive) | скопировать фрагмент в обычную локальную папку, например `%TEMP%\jev` |
| `file changed or reparse point rejected` | Windows: файл изменился между проверкой и чтением или оказался точкой повторной обработки | повторить с обычной локальной копией, которую никто не меняет во время вызова |
| `nonregular file` | Windows: путь указывает не на обычный файл (например, на каталог) | передать путь к файлу |
| `nonregular or duplicate file` | один и тот же файл передан дважды или путь указывает не на обычный файл | убрать повтор, передать путь к файлу |
| `cannot safely read file` | ошибка ОС при открытии или чтении: файла нет, нет прав, файл занят | проверить путь и права |
| `total byte limit 16384 exceeded` | вместе больше 16 384 байт | уменьшить выборку ([сценарий 6](#сценарий-6-большой-файл-по-фрагментам)) |
| `line limit exceeded` | вместе больше 64 строк (включая пустые) или строка длиннее 2 048 байт | сократить выборку; длинные строки (например, JSONL) урезать в копии |
| `binary/control text` | в файле управляющие символы: бинарные данные, цветовые коды ANSI в логах | убрать их из копии (например, выгрузить лог без цветов) |
| `'utf-8' codec can't decode ...` | файл не в UTF-8 (например, Windows-1251) | перекодировать копию в UTF-8 |
| `possible secret rejected` | в тексте есть что-то похожее на ключ или пароль: `sk-or-`, `password:`, `token=`, `api_key=`, приватный ключ | не отправлять эти строки: заменить их пустыми в копии; если это настоящий секрет — проверить, где ещё он лежит |
| `no nonblank lines` | во всех файлах только пустые строки | выбрать другие файлы |
| `unsafe or oversized query` | запрос пустой, длиннее 512 байт, многострочный или похож на секрет | переформулировать короче, одной строкой, без `password:`/`token=` |
| `request too large` | итоговый запрос больше 60 000 байт | уменьшить число строк |
| `set JEV_SEARCH_API_KEY to an inference key ...` | сервер не получил ключ | см. [«Ключ не виден»](#ключ-не-виден) |
| `invalid inference credential` | в значении ключа пробелы, переносы строк или не-ASCII символы | записать ключ заново, без лишних символов |
| `unsupported provider` / `invalid model identifier` | неверные значения `JEV_SEARCH_PROVIDER` / `JEV_SEARCH_MODEL` | исправить или удалить переменную |
| **При и после отправки: списание возможно** | | |
| `HTTP 401; not retried` | ключ недействителен, отозван или выдан другим провайдером (ключ OpenRouter при `JEV_SEARCH_PROVIDER=typesafe` и наоборот) | проверить ключ и провайдера |
| `HTTP 402; not retried` | на счёте или в лимите ключа закончились средства | пополнить баланс или поднять лимит ключа |
| `HTTP 429; not retried` | слишком частые запросы | подождать и повторить позже вручную |
| `HTTP <другой код>; not retried` | 4xx — провайдер отклонил запрос (например, модель недоступна; Decisions API у OpenRouter в альфа-версии); 5xx — сбой у провайдера | проверить модель и статус провайдера; повторять осознанно |
| `network failure (...); not retried; charge may have occurred` | сетевой сбой или таймаут сокета | проверить сеть; запрос мог дойти до провайдера, сверьтесь с кабинетом перед повтором |
| `jev-search timed out; not retried; a charge may have occurred` | вызов не завершился за 330 с | то же: сначала проверить списание, потом решать о повторе |
| `malformed decisions response`, `model mismatch`, `missing cost`, `missing generation id`, `incomplete answer IDs`, `invalid model`, `response exceeds 256KiB`, ошибки разбора JSON вроде `Expecting value: ...` | ответ провайдера не прошёл проверку **после** отправки: запрос, вероятно, оплачен, а оценки не сохраняются | не повторяйте вслепую, сверьтесь с кабинетом OpenRouter; если стабильно — формат API изменился, сообщите в issue |
| **Прочие** | | |
| `jev-search: invalid input or output (...)` | недопустимый символ в аргументе, например NUL (до отправки), или CLI вернул не JSON (после отправки) | проверить запрос и пути; во втором случае сверьтесь с кабинетом перед повтором |
| `jev-search failed: ...` | CLI завершился с неожиданным сообщением | прочитать текст после двоеточия; при повторении — issue с этим текстом без путей и данных |

## 9. Диагностика

### Ключ не виден

Симптом: `set JEV_SEARCH_API_KEY to an inference key ...`, при этом `dry_run` работает.

- **Claude Code, Windows:** переменная задана после запуска клиента. Закройте **все** окна VS Code (не *Reload Window*), все терминалы и сессии Claude Code, откройте заново. Проверьте переменную командой из [раздела 4](#claude-code-на-windows).
- **Claude Code, Linux/VPS:** Claude Code запущен из оболочки, которая не прочитала `~/.bashrc` (старое окно `tmux`, `nohup`, cron, systemd). Перезапустите из новой интерактивной оболочки или задайте ключ в конфигурации службы.
- **Claude Desktop и другие клиенты:** ключ должен быть в блоке `env` конфига; пользовательские переменные они не передают. После правки — полный перезапуск клиента.
- **Проектный `.mcp.json`:** ключа в файле нет; сервер получает его из окружения Claude Code того, кто работает с проектом. Каждый участник задаёт `JEV_SEARCH_API_KEY` у себя, как в [разделе 4](#4-ключ-api).

### Команда не найдена

Симптом: `claude mcp list` показывает ошибку подключения, клиент пишет, что не может запустить `jev-search-mcp` или `uvx`.

- Графические приложения и службы часто не видят `~/.local/bin` в `PATH`. Укажите в `command` полный путь: `where.exe jev-search-mcp` / `where.exe uvx` (Windows) или `which jev-search-mcp` / `which uvx` (Linux/macOS).
- Для терминала: `uv tool update-shell` и новый терминал.

### Первый запуск долгий

При варианте с `uvx` первый старт скачивает зависимости и может превысить таймаут подключения (в Claude Code по умолчанию 30 с). Прогрейте кэш:

```bash
uvx --from git+https://github.com/Vento741/jev-search-mcp@v0.1.0 jev-search-mcp --version
```

Для Claude Code таймаут подключения можно увеличить переменной `MCP_TIMEOUT` (в миллисекундах), заданной перед запуском `claude`: `MCP_TIMEOUT=60000 claude` в bash или `$env:MCP_TIMEOUT=60000; claude` в PowerShell. Надёжнее перейти на `uv tool install`.

### Таймаут на стороне клиента

Многие MCP-клиенты и SDK ждут ответа инструмента около 60 с. Обычный вызов занимает меньше секунды, но если клиент прервал ожидание, запрос к провайдеру **не отменяется** и может быть оплачен. Не повторяйте вызов сразу: проверьте активность в кабинете OpenRouter. В Claude Code предел ожидания инструмента задаётся переменной `MCP_TOOL_TIMEOUT`; собственный предел обёртки — 330 с.

### «files must be absolute paths»

Сервер запускается клиентом в произвольном рабочем каталоге, поэтому относительные пути запрещены. Попросите агента передавать полные пути; правило можно добавить в `CLAUDE.md` ([раздел 7](#7-правила-для-claudemd-и-agentsmd)).

### Проверка офлайн через dry_run

Самый быстрый и бесплатный способ проверить установку, путь к файлу и лимиты — `dry_run`:

> Запусти jev_search с dry_run для файла /home/me/notes/sample.txt и запроса «приветствие».

Если пришёл ответ с `"mode": "dry-run"` и списком `rows`, значит сервер, CLI и проверки файлов работают. **Ключ и сеть при этом не проверяются.** Чтобы проверить их, нужен один реальный поиск по маленькому неконфиденциальному файлу; он стоит доли цента.
